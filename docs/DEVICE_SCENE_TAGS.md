# 设备场景标签初始化

设备管理“标签”页沿用 WVP `/device/classification/tree?categoryType=TAG`，
分类和设备关联分别保存在 `wvp_device_category`、`wvp_device_category_relation`。
VLS 和独立 WVP 前端共用此目录；不在 VLS 数据库复制设备标签。

## 新装、升级与租户边界

新增不可变 Flyway 迁移
`ruoyi-admin/src/main/resources/db/migration/V1_2_12__seed_device_scene_tags.sql`。
新安装通过现有发布 bootstrap 建库后由后端 Flyway 执行；升级也执行同一迁移。
缺少历史分类表的安装由 `CREATE TABLE IF NOT EXISTS` 补齐原模型。
不要对已有数据库执行完整初始化快照，也不要修改已运行迁移。

迁移沿用现有同级名称唯一规则：父分类按 TAG + parent_id=0 + 分类名称匹配，
叶子按 TAG + 预期父分类 ID + 场景名称查重，只补齐这些默认路径中的缺失项。
全局共享目录不表示全树名称唯一；不同父节点下允许同名 TAG。用户分组内的同名
父分类或叶子不影响默认路径补齐，既有用户节点不移动、不重命名，也不修改排序、
祖级、审计字段或设备关联。相同名称的 REGION/GROUP 不影响 TAG 补齐。
父子 ID 使用目标根分类已有或数据库生成的真实 ID，不固定为安装专属数字；
子节点祖级取实际目标父节点祖级。重复执行不增加同级重复节点或改动现有行，
不用忽略 SQL 错误掩盖失败。

分类名称在当前实现中是全局共享目录，没有 tenant_id 列；新租户沿用目录，
无需在租户创建/登录时重复写入。设备关联、VLSTREAM 统计/筛选和写入继续使用
可信租户与原权限；RTSP 保留既有默认租户及部门范围。迁移不新增设备关联、不改
角色权限、不扩展其他旧协议的隔离承诺。分类增改删仍依照既有权限并作用于共享目录。

迁移随升级仅执行一次；升级完成后用户继续可编辑/删除分类，后续重启不会自动复原
用户删除项，也不会将改名后的标签再补回。需要新的补充目录时应另加后续迁移。

## 隔离验证

`node tools/test-device-scene-tags.mjs` 使用本机缓存的 `mysql:8.0.36` 与 `flyway/flyway:8.5.13` 创建唯一命名的
临时容器，只使用 tmpfs 数据目录，不映射端口、不挂载工作数据库、禁用网络，
结束后删除测试容器。可通过 `WVP_SCENE_TAG_TEST_IMAGE` 选择已缓存的 MySQL 镜像；
脚本禁止自动拉取镜像或使用远程 Docker endpoint。

验证空库、发布 bootstrap 分类 schema、已有自定义/部分默认数据、跨父节点同名分类及标签、
名称/顺序/父子关系/祖级、ID/审计字段/关联保留及重复执行。
测试只从发布快照提取两张分类表结构，不导入真实用户、设备或日志记录。
现有分类和 RTSP 租户回归另行运行。隔离测试不代表生产迁移或浏览器端到端验收。
